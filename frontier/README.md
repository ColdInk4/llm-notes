# 前沿索引

这里用于记录更新快、还不适合直接写进稳定章节的内容，例如新模型设置、训练配方、
推理系统、硬件指标、评测榜单和论文线索。等某个主题经过复核、形成更稳定的理解后，
再整理进 `docs/` 对应章节。

## 记录格式

建议每条记录至少包含：

- 主题：模型、架构、训练、数据、推理、系统、硬件或评测。
- 结论：一句话说明值得记录的点。
- 来源：论文、官方博客、模型卡、官方文档、课程材料或其他链接。
- 查阅日期：使用 `YYYY-MM-DD`。
- 状态：`官方`、`论文`、`课程材料`、`社区观察` 或 `待复核`。
- 后续动作：是否需要移动到某个稳定章节，或继续等待更多来源。

示例：

```markdown
## 2026-05-06: Topic Name

- 主题：推理系统
- 结论：一句话记录核心变化。
- 来源：<https://example.com>
- 查阅日期：2026-05-06
- 状态：待复核
- 后续动作：补充官方来源后，合并到第10章推理。
```

## 模型与架构

用于记录 DeepSeek、Qwen、Kimi、GLM、MiniMax、Llama、OLMo 等模型的公开设置、
架构变化、训练 token 数、上下文长度、MoE 配置和注意力机制。

## 训练与数据

用于记录预训练配方、mid-training、SFT、RLVR、数据混合、去重、过滤、合成数据和
scaling law 相关线索。

## 推理与系统

用于记录 vLLM、SGLang、TensorRT-LLM、llama.cpp、PagedAttention、RadixAttention、
speculative decoding、KV cache 压缩、量化和服务调度。

## 硬件与集群

用于记录 GPU/NPU/TPU 指标、互联拓扑、显存带宽、MFU、通信带宽和训练集群公开信息。

## 评测与榜单

用于记录 benchmark、leaderboard、用户流量榜单和真实场景评测。榜单类信息变化很快，
必须保留查阅日期。
