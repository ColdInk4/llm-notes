# 前言

这份笔记面向长期维护的大语言模型知识库，目标是沉淀一条可以反复查阅、持续更新的学习路径。它最初整理自 `datawhalechina/diy-llm` 的文档，之后持续吸收 Stanford CS336、公开论文、模型技术报告和工程实践。

LLM 的技术栈很宽：分词器、Transformer 架构、优化器、数据工程、CUDA kernel、分布式训练、scaling laws、推理系统、评估和后训练都会彼此影响。只从 API 或榜单看模型，容易把这些层次压成一个不可检查的整体；更能迁移的理解，通常来自对底层机制和资源约束的把握。

## 笔记关注什么

CS336 2026 在第一讲里把可迁移知识分成三类，这也很适合作为本仓库的维护原则：

- **Mechanics**：组件到底如何工作，例如 BPE 如何合并、Transformer 如何计算、ZeRO 如何分片、PagedAttention 如何管理 KV cache。
- **Mindset**：如何在有限数据、算力、显存和通信带宽下做取舍。很多工程选择都可以写成 $\text{accuracy}=\text{efficiency}\times\text{resources}$ 的问题。
- **Intuitions**：哪些架构、数据和训练技巧可能有效。

章节优先沉淀前两类机制和方法。涉及具体模型、论文、硬件规格、评测结果或厂商声明时，按 [STYLE.md](../STYLE.md) 的来源与日期约定记录，不另设专门目录。

CS336 Lecture 1 的几个工程立论贯穿本仓库：

- **Leaky abstraction**：每一层抽象（PyTorch / CUDA / NCCL / 集群调度）都会在训练和推理规模变大时"漏出来"。笔记的目标是把抽象边界上的资源账本写清楚，让读者在每一层都能查到具体的 FLOPs、HBM 带宽、通信量、显存开销与质量 trade-off。
- **44× ImageNet 效率**：CS336 Lecture 1 提到 2012-2019 年间 ImageNet 训练效率提升约 44×，主要来自算法（架构、激活、训练技巧）而非纯算力增加。这个数字说明 $\text{accuracy}=\text{efficiency}\times\text{resources}$ 中的 efficiency 仍有相当大的提升空间。
- **SwiGLU 与 "divine benevolence"**：SwiGLU 这类带门控的激活函数在多个模型族里稳定优于 ReLU / GELU，但"为什么"仍在公开研究。Noam Shazeer 在 *GLU Variants Improve Transformer*（arXiv:2002.05202）的结论里把这类只有经验支撑的选择幽默地归因于 "divine benevolence"，CS336 课程转引了这句话。笔记在涉及激活函数选择时按这条经验口径记录。
- **Bitter lesson 的正确理解**：Richard Sutton 的 bitter lesson 主张"能随规模扩展的算法更值得投入"，这一释义把"算法是否重要"的问题重写成"算法是否随规模保持优势"的问题。本笔记把它翻译成具体判断：哪些技巧在大规模下仍稳定、哪些只在 small-scale 实验有效。
- **$\text{accuracy}=\text{efficiency}\times\text{resources}$**：这是仓库常用的判断框架。当一个新技术被提出，先看它主要改善的是 `efficiency`（单位资源的精度）还是 `resources`（总数据 / 总算力 / 总显存 / 总通信），再看两者的乘积是否真正上升。

## 如何阅读

建议先读第 1-4 章建立语言模型的基本组件：分词器、资源核算、Transformer 架构和 MoE。随后读第 5-9 章理解系统成本如何进入训练与推理：GPU 执行模型、GPU 编程、分布式训练、scaling laws 和推理系统。第 10-14 章更偏数据、评估、训练流程、RLVR 和多模态模型，可以按需要穿插阅读；推理行为与能力作为专题补充，连接解码、后训练、工具搜索和系统成本。

维护时把材料分成两层：正文组织稳定学习路径，相关变化信息就近记录在对应小节或章节末；`sources/` 记录 CS336 课件、公开视频、图片和运行 trace 的审阅状态；视频字幕整理稿放在 `sources/captions/`，作为章节复核的视频侧参考。这样既能吸收课程细节，正文也保持在课程主线之内。

每章整理时默认采用一条教学路径：先交代本章要解决的问题和直觉，再进入机制、公式和代码；图片、PDF 截图和运行结果用于解释主线。课件 PDF 或代码讲义中的关键结构图、表格或对比图，只有能帮助首次读者理解时才截取到对应章节并补公开来源；video 讲解用于校准讲义顺序、口头强调点和边界。

阅读时把"某模型用了某技巧"换成下面这类问题：

- 这个技巧节省的是 FLOPs、HBM 带宽、显存容量，还是通信？
- 它是在训练、prefill、generation，还是服务调度阶段起作用？
- 它牺牲了什么：表达能力、稳定性、实现复杂度、可复现性，还是硬件可移植性？
